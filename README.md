# MAYSS — учебный маркетплейс

Полноценный мультивендорный маркетплейс с реальным бэкендом и фронтом, подключённым к API. Pet-проект для собеседований уровня junior backend.

## Стек

**Бэкенд:** Python 3.12, FastAPI, SQLAlchemy 2.0, PostgreSQL (или SQLite для теста), JWT, bcrypt, Pydantic v2, Alembic, pytest

**Фронт:** React 18 без сборки (Babel Standalone), реактивный state через EventTarget

**Инфра:** Docker Compose, nginx для статики

## Запуск

```bash
docker-compose up --build
```

- Фронт: http://localhost:8080
- API: http://localhost:8000
- Swagger: http://localhost:8000/docs

База сидится автоматически.

## Что работает

### Покупатель
- Регистрация и логин (JWT, роли buyer/seller/admin)
- Каталог: фильтры по категории/цене/поиск, сортировка по 4 параметрам, пагинация, grid/list view
- Карточка товара: миниатюры, выбор цвета, количество, табы Описание/Характеристики/Отзывы
- **Кнопка «В корзину» работает везде** — в каталоге, на карточке, на лендинге, в избранном, на странице товара
- **Избранное** — серде на карточке реально работает, синхронизировано между экранами
- **Корзина** — реактивная, счётчик в шапке обновляется сразу. Изменение количества, удаление
- **4-шаговый checkout**: корзина → доставка → оплата → подтверждение. Промокод MAYSS7 даёт −7%
- Сплит заказа по продавцам (если в корзине товары от разных продавцов — создаётся несколько заказов)
- Идемпотентные платежи (повторный клик не дублирует)
- Личный кабинет: дашборд с бонусами, заказы со статусами, **детали заказа** с прогресс-баром доставки
- Адреса доставки: CRUD, выбор по умолчанию, подстановка в чекаут
- Отзывы — оставить можно только на купленный товар (проверка на бэке)
- Профиль/Заказы/Избранное в шапке ведут на разные разделы кабинета

### Продавец
- Создание магазина (если ещё нет профиля)
- **CRUD товаров**: создание, редактирование, архивация
- KPI: выручка, заказы, средний чек, активные товары
- Заказы: список с продвижением статусов (Оплачен → Сборка → В пути → Доставлен)
- Аналитика и финансы (графики — на демо-данных, как в Ozon DevTools)

### Админ (dark theme)
- Реальная статистика по платформе: GMV, пользователи, продавцы, товары, заказы
- Модерация: одобрить/отклонить товары, ожидающие проверки
- Управление пользователями: блокировка/разблокировка (нельзя себя)

### Шапка
- **Счётчик корзины реактивный** — увеличивается при добавлении, очищается при logout
- Поиск с Enter ведёт на каталог с фильтром
- Профиль/Заказы/Избранное — разные секции личного кабинета через query-параметры в hash
- «Войти» если не залогинен

## Архитектура

Монолит на FastAPI с разбиением по доменам:

```
app/
├── api/         # auth, catalog, cart, orders, payments, seller, reviews, favorites, addresses, admin
├── models/      # SQLAlchemy: User, SellerProfile, Category, Product, CartItem, Order, OrderItem, Payment, Review, Favorite, Address
├── schemas/     # Pydantic v2
└── core/        # config, database, security
```

Фронт:
```
frontend/
├── api.jsx          # API клиент + глобальный реактивный store
├── api-bridge.jsx   # маппинг API → формат старых моков, событийная подписка
├── data.jsx         # пустые массивы + статичные fixture для графиков
├── components.jsx   # Header (реактивный), Footer, Icon, Stars, ProductPic, CategoryBlob
└── screens/         # landing, catalog, product, cart, auth, account, seller, admin, pay, ds
```

## Ключевые архитектурные решения

**Реактивный state без библиотек.** Использую `window.dispatchEvent` + кастомные хуки `useCart`, `useFavorites`, `useMe`. Когда что-то меняется (например, `addToCart`), вызывается `refreshCart()`, который перезапрашивает корзину и эмитит событие, и **все компоненты** на экране (включая счётчик в шапке) обновляются автоматически.

**Сплит заказа по продавцам.** Базовая логика любого маркетплейса. При оформлении товары группируются по `seller_id`, создаётся столько Order, сколько продавцов. У каждого — свой статус, своя сумма, продавец видит только свою часть.

**Снапшот цены в OrderItem.** `title` и `price` копируются в момент создания заказа. Если продавец потом изменит цену в каталоге, в чеке покупателя останется та, по которой покупали.

**Стейт-машина заказа.** Переходы статусов жёстко проверяются на бэке. CREATED → PAID → ASSEMBLING → SHIPPED → DELIVERED. Невозможно вручную перепрыгнуть статус.

**Идемпотентность платежей.** Клиент генерирует `Idempotency-Key`, в БД UNIQUE-индекс. Повторный POST с тем же ключом возвращает существующий платёж — это спасает от дабл-клика и retry.

**Отзыв только на купленный товар.** На бэке `POST /reviews` сначала проверяет, есть ли у пользователя `OrderItem` с этим товаром в заказе со статусом `delivered`. Иначе 403.

## Шпаргалка на собес

В порядке убывания эффекта:

1. **Сплит заказа по продавцам** — `app/api/orders.py`. Покажи код группировки + резервацию stock. Объясни почему нельзя одним заказом (разная логистика, разные деньги).
2. **Идемпотентность платежей** — `app/api/payments.py`. Покажи UNIQUE-индекс на idempotency_key и проверку в начале функции.
3. **Стейт-машина заказа** — `app/api/seller.py`, функция `update_order_status`. Покажи словарь `allowed_transitions`.
4. **Снапшот цены** — отдельная таблица `OrderItem` с `title` и `price`, не FK на товар по цене.
5. **RBAC через зависимости FastAPI** — `Depends(require_admin)`, `Depends(require_seller)`. Чисто и типобезопасно.
6. **Реактивный state на фронте без Redux/Zustand** — глобальный store + хуки + кастомные события. Лёгкое решение, понятное для собеса.
7. **Почему монолит, а не микросервисы** — обязательный вопрос. Ответ: преждевременная оптимизация для одного разработчика, разбиение по папкам даёт право в будущем разрезать.

## Что намеренно не сделано

- Реальная платёжка (Stripe/ЮKassa) — есть заглушка, подключение реальной — замена одной функции
- Загрузка картинок в MinIO/S3 — есть `image_url` строкой
- Elasticsearch для поиска — на 20 товарах PostgreSQL ILIKE + индексы достаточно
- RabbitMQ/Celery — не нужны на этом масштабе
- Kubernetes — docker-compose хватит для защиты

Эти пункты — отличный материал для разговора «что бы я добавил при росте».

```bash
pip install -r requirements.txt
export DATABASE_URL="sqlite:///./dev.db"
python seed.py
uvicorn app.main:app --reload
```
